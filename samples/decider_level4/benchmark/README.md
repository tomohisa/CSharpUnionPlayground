# HTTP負荷の測り方

```sh
python3 samples/decider_level4/tests/http_tests.py
python3 samples/decider_level4/benchmark/run.py --students 10000 --concurrency 8
```

各言語・各ストアで同じデータ、同じPython HTTPクライアントを使い、順次実行します。ストアは毎回新規です。100人のウォームアップは同じサーバープロセスで行い、本計測から外します。起動確認はhealthが200になるまで、終了はリクエスト完了後のSIGTERMからプロセスが終了するまでです。ドレイン中の負荷を測った値ではありません。

1クラス10人を単位として、クラス作成、学生登録、履修、個別クエリ、辞退、再履修、授業開始、出席、採点、修了を行います。VO検証による拒否も含めます。クラス内の操作は直列、クラス間は指定した同時実行数です。別にAdvancedの1席へ2人を同じ版で準備・確定する競合を最大50回行い、再判断による満席の拒否を確認します。最後に全学生の個別クエリと全件一覧を3回取得します。

閉ループのHTTP/1.1接続を使い、ワーカーフェーズ内で接続を再利用します。ワーカーフェーズが終わったら接続を明示的に閉じます。各クラスを何度も同じデータで計測するのではなく、学生・クラス・イベントを増やす1つの業務負荷です。

予期した422は業務結果として別カウントにし、予期しないHTTPステータス・通信障害・JSON不整合をエラーとします。予期しないエラーや状態の不一致があれば一連の測定を失敗とし、不完全な表は公開しません。タイムアウトやエラー率を0として隠しません。失敗時のログは `.build/<language>-server.log` に残ります。

RSSはpsで100msごとにサーバーPIDを観測した最大値です。クライアント、ビルドプロセス、他言語のサーバーは含みません。サンプリング間に一瞬だけ増えたメモリは捉えられません。入力・出力・JIT・GC・JSONイベント・ライブ投影を含むプロセス全体の値です。

raw dataにはフェーズ別時間、API種別別p50/p95/p99、レスポンスbyte数、クライアントCPU時間、各SDK版、ソースSHA-256、OpenAPI SHA-256を保存します。同じローカルマシンで負荷側とサーバーが動くため、純粋なサーバーの上限性能ではありません。到着率を固定するopen-loopの飽和・過負荷試験は今回含めていません。
