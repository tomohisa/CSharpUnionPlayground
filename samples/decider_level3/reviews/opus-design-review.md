# Claude Opusによる設計レビュー

2026-11-11にClaude CLIの読み取り専用ツール（Read／Glob／Grep）で、claude-opus-5-5へ設計レビューを依頼しました。ファイルの変更やビルドの実行は依頼していません。レビュー対象は7言語の共通ライブラリ、C#／TypeScriptの接続・投影、Goのコピー処理などです。レビュー時点のコードは実装途中であり、コンパイル成功を認定するレビューではありません。

レビューでは、ジェネリックなEでドメインの閉じたイベント集合を保つ境界、全体ウォーターマークと条件クエリによる原子的追記、競合後の再判断を妥当と評価しました。次の指摘を実装へ反映しました。

| 指摘 | 反映 |
|---|---|
| 購読者の例外で、コミット済み追記が失敗に見える | 通知失敗を分離し、他の購読を継続。独立カウンターテストで確認 |
| 購読が切り離された後に古い一覧を返す可能性 | listenerFaultsを公開し、学校アプリは投影障害時の一覧取得を拒否 |
| Drop／Attend／Assessの整合性範囲が広い | student OR classからclassへ絞る |
| C# TagのImmutableArrayが既定のrecord等価性では構造比較されない | Equals／GetHashCodeを実装し、HashSetでも同値を確認 |
| SwiftのSendableとロックの契約が不十分 | payload／closureへSendable制約、障害数もロック付き取得、Codableは条件付き適合 |
| Javaの投影状態と位置を別々に取得 | Snapshotとして同じロックで返す |
| Rustのfnポインターが設定を捕捉できない | クロージャを受ける設計へ変更 |
| 判断後に監査用の読み取りをやり直す | 件数をTicketへ持たせ、元の読み取りと一致させる |
| Goのコピー契約を明確にする必要がある | 名簿ヘルパーは既にコピーしていた点を確認し、Snapshot用のClassState内sliceも明示的にコピー |

追加の提案として、Candidate<E>をドメイン側で組み立てる段階をやめ、ストアへdescribe関数を渡す形を採用しました。Emitは元のEをそのまま持ち、メタ情報の生成・取り込み時の検証をライブラリへ集約しています。

その後、コマンドストアのinterface／trait／protocolも分離し、学校型を含めない独立ビルドで7言語の共通部品を検証しています。Javaの公開パッケージ、Swiftの別モジュールからの利用も対象です。

購読をロック内で同期配信する非再入の契約、Swiftのfatal errorなど回復不能なプロセス終了、commandIdの永続的冪等性を持たない点は、サンプルの制約として共通READMEに明記しています。レビューの指摘と、実際に実行したテストの結果は区別しています。

## 最終レビューでの追加指摘と回帰テスト

同じモデルで最終の読み取り専用レビューを行い、ライブラリの学校依存がないことと、型Eを保つ境界、判断に必要なタグの範囲、条件付き追記と再判断を確認しました。レビュー自体はビルドや実行をしていません。

追加で指摘されたC#のカルチャ依存の履修キー順序と、不正な出席履歴の無視を修正しました。17シナリオには大文字小文字・補助文字の一覧順を加え、不正な出席履歴も拒否する回帰入力にしています。7言語の一覧順はUTF-8順です。

Javaの一覧取得ではSnapshotを一度だけ取得し、通知のAssertionErrorも分離します。Rustでは検証途中のpanicからロックを再取得できるようにし、ログへ追加するコピーもバッチ全体を準備してから行います。Goの手動TicketもCommit時にPreparationの不変条件を検査します。SwiftのタグはUnicodeスカラー単位で比較し、学校のIDはNFCで統一して与える契約を文書化しました。

同期・非再入の購読、純粋なコピー関数、commandIdが冪等キーではない点は、レビューでも文書化済みのサンプル制約として区別しています。HandlingResultのstatusは現状では報告用の文字列で、閉じた結果型へ統一する余地があるという任意の提案も残しています。
